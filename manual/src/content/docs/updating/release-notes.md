Before you download a version, you can see what it changes. The notes are the ones written for the release on GitHub, shown in the update dialog.

## Steps

1. When the update dialog offers a version, click *What has changed* under the text. The notes unfold in the dialog; long ones scroll.
2. Read the **Highlights** first, if there are any. They are written by hand and say what you will notice: a new feature, a changed default, something that works differently.
3. Look for a quoted paragraph at the top or in the middle. That is where a release warns you about something — a setting that needs to be set up again, a step you take by hand, a version you cannot go back from.
4. Then decide: *Download*, *Remind me later* or *Skip this version*. See [Update Snotra Agent](../update-snotra/).

The box is also there in the step *Ready*, after the download, in case you want to read the notes before the restart.

## What you see

Snotra shows what changed and leaves out what only matters on GitHub: the lines of the generated list lose the name of the author and the pull request link, and the list of new contributors and the link to the full comparison are dropped. What is left are the highlights and one line per change.

The notes are in English in every interface language, because that is how the release is published. For the whole text with every link — the pull requests, the full comparison — open the [releases on GitHub](https://github.com/kkrafft1999/snotra/releases). On an installation that cannot update itself, the dialog's button *Open release page* takes you there. On GitHub you also find the notes of versions you skipped or of older ones.

## If it doesn't work

- **There is no *What has changed* box.** The release has no notes, or Snotra could not read them. The release page still shows what there is.
- **You want the notes of a version you already installed.** The dialog only shows them while an update is offered. Read them on the [releases page](https://github.com/kkrafft1999/snotra/releases).
