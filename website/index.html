Software wird nicht gekauft.Sie wird beschrieben.

Snotra AI ist die Werkbank dafür: eine Desktop-App, die auf genau einen Ordner zeigt. Das Fachwissen liegt als Textdatei daneben, die Fähigkeiten stecken in Werkzeugen, das Modell ist austauschbare Ware — auch gegen eines, das lokal auf deinem Rechner läuft. Die Richtung ist gesetzt: angebunden wird, was ohnehin da ist — jedes CLI auf deiner Maschine. Kein eigener Server, kein Konto, keine Telemetrie.

Vier Entscheidungen, die alles andere bestimmen

Keine Feature-Liste. Was Snotra ausmacht, steckt im Schnitt der Software selbst.

01 Modell

Austauschbar, nicht ausgeliefert

Im Kern sitzt ein Port, kein Anbieter. OpenAI, Anthropic, Google — oder lokal über Ollama und MLX-LM, dann verlässt kein Wort deinen Rechner.

Du wettest nicht auf die Roadmap eines Konzerns.

//modell-pille aus dem composer — anklickbar

Fünf Anbieter, ein Port. Zwei davon rechnen auf deinem Rechner.

02 Wissen

Dein Fachwissen bleibt eine Datei

Ein Skill ist ein Ordner mit einer SKILL.md im offenen Agent-Skills-Format. Versionierbar in Git, lesbar für Menschen, übertragbar auf andere Werkzeuge — kein Datenbankeintrag bei einem Anbieter.

//ein skill, wie er auf der platte liegt

.agents/skills/angebot/ SKILL.md vorlage-angebot.md preisliste.csv
.agents/skills/angebot/SKILL.md git-versioniert 
---
name: angebot
description: Erstellt Angebote nach Hausvorlage.
  Verwenden, wenn ein Angebot, ein Nachtrag oder
  eine Preisauskunft gefragt ist.
---

# Angebot erstellen

1. Vorlage aus `vorlage-angebot.md` lesen.
2. Positionen aus `preisliste.csv` ziehen.
3. Rabattstaffel ab 10 Tagen anwenden.
4. Vor dem Schreiben Summe gegenrechnen.

03 Anschluss

Verbindet sich mit allem, was schon da ist

Jedes Kommandozeilen-Werkzeug auf deinem Rechner wird zum Werkzeug des Modells — git, docker, az, das CLI deines Hauses. Kein Konnektor, kein Adapter, keine Integrationsprojekte: Ein Skill beschreibt das Werkzeug, den Rest macht die Shell.

shell_execute: kommt mit der nächsten Version MCP-Server in Arbeit

04 Kontrolle

Nichts passiert ohne dich

Jeder schreibende, ausführende oder externe Aufruf kommt vorher als Karte in den Chat: Zielpfad, vollständiger Befehl, Vorschau.

Für Ausführung gibt es bewusst kein „für diese Sitzung merken“.

shell_execute: kommt mit der nächsten Version

//echte freigabe-karte — entscheide hier

Ausführung bestätigen

Snotra möchte einen Befehl in zsh ausführen (shell_execute).

Wirkung
Ausführen
Shell
zsh (Login-Shell)
Arbeitsordner
~/Projekte/angebote
Grund
Stand der Ablage vor dem Schreiben prüfen
Modus
Intelligent

Achtung: Der Befehl läuft mit deinen Rechten und ist nicht auf den Projektordner begrenzt.

Vorschau: Befehl 
git status --short && git log -3 --oneline

Für „Ausführen“ ist nur eine Einzelentscheidung möglich.

Wartet auf deine Entscheidung. Esc lehnt ab.
