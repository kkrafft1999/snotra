                Run Python

                Careful: run_python runs the model’s code — isolated on macOS and Linux, with your full rights on Windows.

                On macOS and Linux the code runs in a sandbox: it can write only inside the project folder and a temporary folder, cannot read keys, cloud credentials or browser data, and reaches the network only for the domains named on the approval card. It can still read your other files. On Linux the sandbox needs the packages bubblewrap, socat and ripgrep.

                On Windows there is no sandbox yet: the code can read and write anywhere, reach the network and start programs. Snotra shows you the full source before every run for approval, and the card says whether the run is isolated. Only switch this on if you are aware of that.

                Leave empty to search for Python 3 automatically.

                Your own path — a venv with pandas, say — decides which packages the model has. Snotra never installs anything itself.

                Run shell commands

                Careful: shell_execute runs the model’s commands — isolated on macOS and Linux, with your full rights on Windows.

                On macOS and Linux every command runs in a sandbox: it can write only inside the project folder and a temporary folder, cannot read keys, cloud credentials or browser data, and reaches the network only for the domains named on the approval card — pip and npm installs get their registry automatically. It can still read your other files, and tools that verify certificates through the macOS keychain (gh, terraform) cannot reach the network inside it. On Linux the sandbox needs the packages bubblewrap, socat and ripgrep.

                On Windows there is no sandbox yet: a command can do everything you can do in a terminal yourself. Snotra shows you the full command, the shell, the working directory and whether the run is isolated before every run for approval; recursive force-delete, disk operations and rewriting Git history are blocked. In “Auto” mode a command runs without asking. Only switch this on if you are aware of that.

                Sandbox for this workspace

                Applies to run_python and shell_execute, in this folder only.

                Switch it off only when the sandbox gets in the way of something legitimate here: writing outside the folder, gh or terraform without network, an older pip. You confirm that in the system dialog. The setting is stored with your permissions, not in the folder, so a checked-out repository cannot switch it off for itself.

                      A skill is a SKILL.md with instructions on how the model should work — ticked skills go into the system prompt.

                      System skills ship with the app and are on by default. Folder skills are read from three places: .agents/skills in the open folder, globally from ~/.snotra/skills — the recommended place — and still from the old location ~/.agents/skills. On a name clash the open folder wins, then ~/.snotra/skills. Directories belonging to other tools, .claude for instance, are not read. Folder skills are somebody else’s content and are loaded only after you pick them.

                      ~/.snotra is Snotra’s own user directory — the root for user data that belongs to Snotra; skills is its first inhabitant. Snotra neither creates the directory nor moves anything into it.

                      Type a / in the chat and Snotra suggests a fitting skill below the input, based on what you have written so far. Taking it up stays your click. “From the descriptions” runs on your machine and costs nothing; “Ask the model” also understands jargon, but sends the line and the skill names to the provider and takes a moment.

                          Environment
                          Gives the model the working directory, platform, shell and today’s date.

                          Without this, the model guesses the platform for shell commands and dates “last week” by its training cut-off. What is sent: the absolute path of the open folder — it contains your user name —, whether there is a Git repository in it, platform and system version, the shell used by shell_execute (only when that is on), today’s date and the Snotra version. All of it goes to the provider with every request.

                          Project instructions
                          Puts the project instructions from AGENTS.md into the system prompt.

                          Up to three files are read: <folder>/.agents/AGENTS.md from the open project, ~/.snotra/AGENTS.md (applies everywhere) and ~/.agents/AGENTS.md (applies everywhere, the older place, still read). All that exist add to each other and apply together — none replaces another. Each file contributes at most 20,000 characters; anything longer is visibly truncated.

                          Inside the project only .agents/ counts. An AGENTS.md directly in the folder root is not read, even though that is the more common form elsewhere.

                          The content is instruction, not data — unlike tool results it changes how the model behaves. Open somebody else’s folder and you take on their instructions too; this switch is the emergency brake for that.

                          Appearance
                          Light or dark interface — a button in the title bar up to v1.7.3.

                          Unlike the other settings, this choice stays on this device: it has to be settled before the window is built, or the light interface would flash up briefly at every start.

                          Takes effect at once — the interface switches language without a restart.
